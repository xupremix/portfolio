Create `src/components/Nav.astro`. Root element `<header id="site-nav">`, sticky at the top
(`sticky top-0 z-50 h-3xl`, 64px, matching UI-SPEC's fixed nav-bar-height note), idle-state classes
`bg-mantle/10 backdrop-blur-md border-b border-border/50 transition-colors`. Add an Astro scoped
`<style>` block defining a `.is-scrolled` rule that sets `background-color: var(--color-mantle)` and
removes the blur, so a JS-toggled class swaps the idle glass effect for a fully solid Secondary(30%)
background once the page is scrolled. Add one small inline `<script>` with no imports and no
framework: it selects `#site-nav`, defines a function that toggles the `is-scrolled` class based on
`window.scrollY > 0`, calls it once immediately, and attaches it to `window`'s `scroll` event with
`{ passive: true }`. This is the shell's one piece of JS, matching UI-SPEC's explicit allowance for
"a small IntersectionObserver... keep JS to near-zero" — do not add any other client-side script to
this component.

Inner layout: a flex row with the site name as a left-aligned link to `/`
(`text-label font-semibold text-text`, the resting visual focal point per UI-SPEC). On the right,
desktop-only (`hidden md:flex`, gap-lg) render two plain anchor links — "Projects" to `#projects`
and "Skills" to `#skills` — styled `text-text hover:text-accent focus-visible:text-accent
focus-visible:ring-2 focus-visible:ring-accent/60 transition-colors`, followed by the "Contact" CTA
as a filled button-styled anchor to `#contact`: `bg-accent text-base rounded-md px-md py-xs
text-label font-semibold focus-visible:ring-2 focus-visible:ring-accent/60 focus-visible:outline-none`.
The CTA is visually distinct from the plain links (filled, not just colored text) per UI-SPEC's
Copywriting Contract, and per UI-SPEC's Color section carries the same focus ring treatment as every
other interactive element (no exceptions).

Mobile hamburger toggle: a visually-hidden `<input type="checkbox"
id="nav-toggle" class="peer sr-only">`, followed by two `<label for="nav-toggle">` elements, both
sized `w-11 h-11` (44px, the explicit UI-SPEC accessibility tap-target exception — not one of the
named spacing tokens) and centering a 24px icon. Because a plain `<label>` has no native keyboard
focus/activation, both labels additionally get `id="nav-toggle-open"` / `id="nav-toggle-close"`,
`tabindex="0"`, `role="button"`, and `focus-visible:ring-2 focus-visible:ring-accent/60
focus-visible:outline-none` — matching every other interactive element's focus treatment per
UI-SPEC's Color section. The first renders `<Icon name="lucide:menu"
width={24} height={24} />` plus visually-hidden text reading "Open menu", classed `md:hidden flex
peer-checked:hidden`. The second renders `<Icon name="lucide:x" width={24} height={24} />` plus
visually-hidden text reading "Close menu", classed `md:hidden hidden peer-checked:flex`. Because
both labels target the same checkbox, exactly one is visible at any time via the `peer-checked:`
variant, so the accessible name toggles between "Open menu" and "Close menu" purely through CSS.
Extend the Nav.astro inline `<script>` (the same one that already handles the scroll-triggered
`is-scrolled` swap — still the shell's only script, no new file) with a few lines that select both
label elements by their new ids and, on `keydown` for `Enter` or `Space`, prevent default scrolling
and toggle `#nav-toggle`'s `checked` property directly — this makes the toggle fully keyboard-operable
without abandoning the CSS-only visual mechanism.
Below the toggle, add a dropdown `<nav class="md:hidden hidden peer-checked:flex flex-col gap-md
absolute top-3xl inset-x-0 bg-mantle p-lg border-b border-border">` containing the same
Projects/Skills links plus the Contact CTA, stacked vertically, shown via the same `peer-checked:`
mechanism.

Create `src/components/Footer.astro`: `<footer class="bg-mantle border-t border-border px-lg py-lg

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Footer icon-links -> external destinations | GitHub/email icon-links ship with `href="#"` in Phase 1 (Phase 4 wires real destinations); until then they are inert, not user-input-driven |
| Nav/Footer markup -> browser rendering | Static Astro components render to static HTML with zero user-controlled input in this phase |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-------------------|
| T-01-04 | Spoofing | Footer.astro icon-link placeholders (href="#") | low | accept | Links are inert self-referencing anchors, not redirects to attacker-controlled destinations; explicit TODO(phase-4) comments prevent them from being mistaken for finished, shippable-as-final links; Phase 4 (CONT-01) closes this before any real launch |
| T-01-05 | Tampering | Inline scroll-listener script in Nav.astro | low | mitigate | Script is authored entirely in-repo (no third-party/remote script src, no eval, no innerHTML with dynamic data) — it only reads window.scrollY and toggles a class; verified by code review that it contains no dynamic HTML injection |
| T-01-06 | Information Disclosure / Injection | Entire shell (Nav/Footer/Layout/index/404) | low | accept | No forms, no query-string rendering, no user input processed anywhere in Phase 1; the static shell has no attack surface for XSS/injection — revisit when a form or dynamic user input is introduced in a later phase |

</threat_model>
