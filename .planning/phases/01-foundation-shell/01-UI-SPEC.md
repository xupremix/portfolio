## Design System

| Property | Value |
|----------|-------|
| Tool | none — no shadcn/component-library init. **[DEFAULT, rationale below]** |
| Preset | not applicable |
| Component library | none — hand-built `.astro` components styled with Tailwind utility classes |
| Icon library | lucide, via `astro-icon` (build-time inlined SVG, zero runtime JS) |
| Font | Inter (UI/body) + JetBrains Mono (technical accents), self-hosted via `@fontsource` packages |

**Why no shadcn:** shadcn's component model targets React (Radix primitives + client-side interactivity). This project is Astro-only, static-first, "minimal JS shipped" per PROJECT.md constraints, with no React islands planned. A handful of hand-built Astro components (nav, footer, card, badge, button) styled directly with Tailwind fully covers this site's needs without pulling in a React runtime. If a later phase introduces genuine client-side interactivity that benefits from Radix primitives, revisit this decision then — do not add it preemptively.

**Aesthetic direction [DEFAULT]:** Dark-mode-only, single theme (no light/dark toggle in v1 — avoids theme-switching JS, keeps the "minimal JS" constraint intact, and a toggle is not in REQUIREMENTS.md). Dark, near-black surfaces with a single vivid cyan accent read as modern/technical and are a well-established, low-risk pattern for systems/ML engineer portfolios aimed at technical recruiters. This is a first-pass call, not a locked user decision — flag for confirmation at next `/gsd-discuss-phase` or UAT if the user wants light mode instead.

## Spacing Scale

Declared values (must be multiples of 4), standard 8-point scale — no upstream override, using system default:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, badge inline padding |
| sm | 8px | Compact element spacing (nav link gaps, tag chip padding) |
| md | 16px | Default element spacing, card internal padding |
| lg | 24px | Section internal padding, nav/footer vertical padding |
| xl | 32px | Layout gaps between major shell regions |
| 2xl | 48px | Major section breaks (between page sections) |
| 3xl | 64px | Page-level top/bottom spacing, hero-scale gaps |

Exceptions:
- Mobile nav hamburger toggle: 44px × 44px minimum hit target (touch-target accessibility floor), even though the icon glyph itself renders at 24px — pad the tappable button to 44px.
- Nav bar height: 64px fixed (maps to `3xl` token) for both desktop and mobile, so scroll-offset math for anchor links (`#projects`, `#skills`, `#contact`) stays constant across breakpoints.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (Regular, Inter) | 1.5 |
| Label | 14px | 600 (Semibold, Inter or JetBrains Mono) | 1.4 |
| Heading | 28px | 600 (Semibold, Inter) | 1.2 |
| Display | 48px | 600 (Semibold, Inter) | 1.1 |

Exactly 4 sizes (14/16/28/48), exactly 2 weights (400/600) — no exceptions.

**Font pairing rationale:** Inter for all UI/body/heading copy — highly legible, neutral, works at every size the contract declares. JetBrains Mono is a font-family variant on the **Label** role only (same 14px/600/1.4 tokens — it is not a third size or weight), reserved for: nav "role" microcopy if used (e.g. a small `ML Engineer` tag), tech-stack badge text on project cards (Phase 3), and any code-like inline text. This is a deliberate, restrained nod to the systems/Rust/ML engineering identity without becoming a gimmick — do not use monospace for body paragraphs or headings.

**Delivery:** Self-host via `@fontsource/inter` and `@fontsource/jetbrains-mono` (or Astro's built-in font API if the scaffolded Astro version supports it) — no external Google Fonts request, keeps the site fast per the "fast-loading" project constraint. Load only the weights actually used: Inter 400 + 600, JetBrains Mono 600.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0B0F14` (near-black, cool slate) | Page background, all default surfaces |
| Secondary (30%) | `#131922` (slightly lighter dark slate) | Cards, nav bar, footer, section alternation |
| Accent (10%) | `#22D3EE` (cyan-400) | See reserved-for list below — nothing else |
| Destructive | `#F87171` (red-400) | Not applicable in Phase 1 (no destructive actions exist on a static portfolio); reserved token for any future form-validation or broken-link error text only |

Supporting neutrals (not part of the 60/30/10 split, needed for text contrast):
- Primary text: `#E6EDF3` (near-white) on dominant/secondary surfaces — passes WCAG AA for body text.
- Muted/secondary text: `#8B949E` (mid-gray) for captions, footer copyright line, de-emphasized metadata.
- Hairline borders/dividers: `#1F2733` (subtle, barely-there separator between nav/footer and page content).

**Accent reserved for** (explicit — never "all interactive elements"):
- Primary CTA button fill (e.g. nav "Contact" button)
- Active/current nav-link indicator (underline or dot, not full link recoloring)
- Link hover/focus state (text or underline shifts to accent on hover, not by default)
- Keyboard focus ring on all interactive elements (accessibility requirement, uses accent at reduced opacity as ring color)
- The "in progress" badge outline/text on the evolcpp project card (Phase 3 — noted here so Phase 1's badge component primitive is built with this in mind)

Do not use accent for: body text color, large surface fills, decorative backgrounds, or more than one element type per view beyond this list.

## Copywriting Contract

Phase 1 is the shell (nav + footer + global chrome) — it has no dynamic data, forms, or destructive actions. Fields below are filled with what genuinely applies to the shell; items not applicable to a static shell are marked N/A with rationale rather than invented.

| Element | Copy |
|---------|------|
| Primary CTA | Nav bar button, label: **"Contact"** — accent-filled button, links to `#contact` (Phase 4 section). This is the shell's one CTA; Hero's own CTA is defined in Phase 2's UI-SPEC. |
| Empty state heading | N/A for Phase 1 — no data-driven lists exist in the shell (project grid empty-state, if ever needed, belongs to Phase 3's UI-SPEC). |
| Empty state body | N/A for Phase 1 — see above. |
| Error state | Site-wide 404 page (part of the shell, Astro convention `src/pages/404.astro`): Heading **"Page not found"**, body **"That page doesn't exist. Head back to the homepage."**, with a link/button back to `/`. This is the one error-adjacent surface that belongs to Phase 1. |
| Destructive confirmation | N/A — this project has no destructive actions (static content site, no delete/forms/account actions anywhere in scope). |

**Nav link labels** (anchor-scroll to in-page sections, single-page site): `Projects`, `Skills`, `Contact` — plus the "Contact" CTA button described above doubles as the fourth nav item, rendered as a filled button rather than a plain link to visually differentiate the CTA from navigational links.

**Footer contract:** Left/start: `© {current year} Filippo Lollato` in muted text. Right/end (or centered below on mobile): icon-links for GitHub and email — Phase 1 builds the structural slots (icon + accessible `aria-label`), Phase 4 (CONT-01) wires the actual `href="mailto:lollatofilippo@gmail.com"` and `href="https://github.com/xupremix"` values. Do not hardcode placeholder URLs that could ship unfixed — leave them as an explicit `TODO(phase-4)` comment in the component if built before Phase 4 lands.

## Component Inventory (Phase 1 scope)

Explicit list of what this phase builds, so planner/executor scope matches this contract:

- `Layout.astro` — base HTML shell: `<head>` boilerplate, font loading, global CSS import, slot for page content.
- `Nav.astro` — sticky/fixed header, 64px height. Transparent + backdrop-blur over hero on load, transitions to solid `Secondary (30%)` background once scrolled (CSS-only, `position: sticky` + a small IntersectionObserver or pure CSS `@supports`/scroll-driven-animation if targeting modern browsers — keep JS to near-zero). Desktop: horizontal link row + CTA button, right-aligned (or centered, executor's call within this contract). - Global Tailwind theme config (`tailwind.config.*` or Astro/Tailwind v4 CSS-first `@theme` block) encoding the Spacing, Typography, and Color tokens declared above as reusable tokens/utilities — this is the literal "design system" deliverable for SETUP-02.
