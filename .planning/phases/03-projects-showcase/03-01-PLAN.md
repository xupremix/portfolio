Icons: `import { Icon } from 'astro-icon/components'` then
`<Icon name="lucide:github" width={16} height={16} aria-hidden="true" />` — `lucide:github` is
already used in `Footer.astro` (confirmed working, no new icon dependency needed). Do not add
`lucide:arrow-up-right` to the secondary pill list — UI-SPEC marks it optional and this plan
deliberately keeps the pills icon-free to match the "lighter-weight than the featured cards" framing.

Focus ring pattern (apply to every interactive element — card links, secondary pills — matches
Nav.astro/Hero.astro/Footer.astro exactly):
`focus-visible:ring-2 focus-visible:ring-accent/60 focus-visible:outline-none`

Known Gotcha (from PROJECT.md "Known Gotchas" — read it before writing any `max-w-*`/`w-*`/`h-*`
class in this phase): this project's `@theme static` block names its custom spacing tokens
`xs/sm/md/lg/xl/2xl/3xl`, the exact same key names Tailwind v4 reserves for its built-in
`max-w-*`/`w-*`/`h-*` size scale. That means a class like `max-w-2xl` silently compiles to this
project's 48px spacing token, NOT a real ~672px container width — this already broke Hero.astro in
Phase 2 and was fixed with an explicit arbitrary value (`max-w-[42rem]`). This phase's `Projects.astro`
needs a real 1152px container width, so it MUST use the literal arbitrary-value class
`max-w-[72rem]` — never any of the `max-w-{xs,sm,md,lg,xl,2xl,3xl}` names. `ProjectCard.astro`'s
`h-full` class is unaffected by this bug (`full` is not one of the project's custom spacing-token
names, so `h-full` compiles to Tailwind's normal 100% height utility) — use it as-is, do not replace
it with anything else.
