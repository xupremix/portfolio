## Spacing Scale

Declared values (must be multiples of 4) — **identical to Phase 1/2, no new tokens**:

| Token | Value | Usage in this phase |
|-------|-------|-------|
| xs | 4px | Gap between tech badges within a card's badge row |
| sm | 8px | Gap between card title and status badge; gap between secondary-list pills |
| md | 16px | Card internal padding (`p-md`); gap between card title and description |
| lg | 24px | Grid gap between cards (`gap-lg`); section horizontal padding on mobile (`px-lg`, matches Nav/Footer) |
| xl | 32px | Gap between featured grid and the "More on GitHub" secondary block; section horizontal padding on tablet+ (`px-xl`, matches Nav/Footer) |
| 2xl | 48px | Gap between section title/subtitle and the featured grid |
| 3xl | 64px | Section top/bottom padding (`py-3xl`), matching the "page-level spacing" role this token already plays in Phase 1/2 |

**Content-width exception [DEFAULT] — gotcha called out explicitly:**
- The `#projects` section wraps its content in a `max-w-[72rem] mx-auto` container (1152px) so the 6-card grid and secondary list don't stretch edge-to-edge on very wide viewports. **Must be written as the literal arbitrary value `max-w-[72rem]` — never `max-w-2xl`/`max-w-3xl`/etc., which resolve to this project's 48px/64px spacing tokens instead of a real container width** (see Context Sources gotcha note above; same class of bug Phase 2 hit and fixed with `max-w-[42rem]` on Hero's text column).
- No other new content-width values are introduced by this phase; card width itself is controlled by the grid (`grid-cols-*`), not by a `max-w-*` utility on the card.

Exceptions beyond the above: none.

**Phase 3 element-to-role mapping [DEFAULT]:**

| Section title ("Projects") | Display (48px/600/1.1) | Inter | `<h2>`. Matches Hero's name scale — Phase 3 is the site's first real content section, so it gets the same visual weight Phase 2 gave the hero name, marking a clear section boundary as the user scrolls. |
| Section subtitle | Body (16px/400/1.5) | Inter | One sentence under the title, `text-subtext` (muted) — sets expectation before the grid, does not repeat the title's information. |

| Card description | Body (16px/400/1.5) | Inter | 1–2 sentences, primary text color (not muted — this is core content, not de-emphasized metadata, per Phase 1's own rule reserving `subtext` for captions/copyright/metadata). |
| Tech-stack badge text | Label (14px/600/1.4) | JetBrains Mono | Renders via the existing `Badge.astro` (`variant="default"`), which already hardcodes `text-label font-mono` — no override needed. |

| Team-credit line ("Team project — repo by ale-bena") | Label (14px/600/1.4) | Inter | Plain `<p>`, `text-subtext` — de-emphasized metadata about authorship, distinct from the description. |
| Card link ("View on GitHub") | Label (14px/600/1.4) | Inter | Matches the existing secondary-link pattern already shipped in `Hero.astro` ("Get in touch"): plain text + icon, not a filled button. |
| "More on GitHub" heading | Heading (28px/600/1.2) | Inter | `<h3>`, one step down from the Display-size section title, signaling this is a secondary/lower-emphasis block. |
| Secondary-list repo pills | Label (14px/600/1.4) | Inter | Plain repo name text, e.g. "mlgui" — no monospace here (monospace is reserved for the Badge component's tech/status tags per Phase 1's font-pairing rule, not for every code-adjacent word). |

## Color

**Identical palette as Phase 1/2 — no new hex values introduced:**

| Role | Value | Usage in this phase |
|------|-------|-------|
| Dominant (60%) | `#1E1E2E` (`--color-base`) | Page/section background — `#projects` sits flush with the page, same as Hero |
| Secondary (30%) | `#181825` (`--color-mantle`) | Each `ProjectCard` surface (`bg-mantle`), giving cards visual separation from the page background — first real use of this token as a card surface (Phase 1 reserved it for "cards, nav bar, footer, section alternation") |
| Accent (10%) | `#CBA6F7` (`--color-accent`) | See reserved-for list below |
| Destructive | `#F38BA8` (`--color-destructive`) | Not applicable — no destructive actions in this phase |

Supporting neutrals (unchanged from Phase 1/2): Primary text `#CDD6F4` (`--color-text`), Muted text `#A6ADC8` (`--color-subtext`), Hairline border `#313244` (`--color-border`).

**Accent reserved for (Phase 3 additions — same budget discipline as Phase 1/2, no blanket accent use):**
- The `evolcpp` card's "In Progress" status badge (`Badge variant="progress"` → `border-accent text-accent`) — this is the literal use case Phase 1's Color section pre-declared: *"The 'in progress' badge outline/text on the evolcpp project card."*
- Card link ("View on GitHub") and secondary-list pill hover/focus state only (default state uses primary text color `#CDD6F4`) — reuses Phase 1's existing "link hover/focus state" reservation, not a new grant.
- Keyboard focus ring on every interactive element in this phase (card links, secondary-list pills) — reuses Phase 1's existing focus-ring reservation, same `focus-visible:ring-2 focus-visible:ring-accent/60` pattern already shipped in `Nav.astro`/`Hero.astro`.

**Explicitly NOT accent:**
- Card titles stay in primary text color `#CDD6F4`, not accent — visual dominance comes from Heading-size type weight, matching how Hero's name (Display size, primary text, not accent) stayed disciplined in Phase 2.
- The `ASA Autobots` team-project status badge uses `Badge variant="default"` (neutral `border-border`/`text-subtext`/`bg-mantle`), **not** `variant="progress"`/accent. Accent-outline is reserved exclusively for the in-progress signal per Phase 1's pre-declared reservation; using it for the team badge too would blur the two meanings (in-progress vs. team-credited) that this phase's success criteria require to read as visually distinct from each other.
- Tech-stack badges also use `Badge variant="default"` uniformly across all six cards and all technologies (Rust, Python, Node.js, etc.) — **no per-technology pastel color-coding.** Phase 1's Color section floated an optional "secondary pastel set" (`#94E2D5` teal / `#89DCEB` sky / `#FAB387` peach / `#A6E3A1` green) for tech tags as a "may" — not a requirement. This phase deliberately does not implement it: `Badge.astro` ships with exactly two variants today, adding a third color axis would mean extending a component that's already built and shipped, plus a technology→color mapping to maintain forever across every future project addition. Uniform neutral tags keep the accent budget disciplined and avoid visual noise across six cards × multiple tags each. **[DEFAULT — deviates from Phase 1's speculative note, by design.]**

## Component Inventory (Phase 3 scope)

- `src/components/ProjectCard.astro` — new component, one instance per featured project:
  - Props: `{ name: string; description: string; tech: string[]; href: string; status?: 'in-progress' | 'team'; teamCredit?: string }`
  - Structure: `<article>`, `bg-mantle border border-border rounded-md p-md flex flex-col gap-md h-full` (full height within its grid cell, so all cards in a row bottom-align even if content length varies slightly)
  - If `status === 'in-progress'` → render `<Badge label="In Progress" variant="progress" />` near the title. If `status === 'team'` → render `<Badge label="Team Project" variant="default" />` near the title **and** the `teamCredit` text line (`text-label text-subtext`) directly below the title. Neither badge renders for the other 4 cards.
  - Title (`<h3>`, Heading role, `text-text font-semibold`) → description (`<p>`, Body role, `text-text`) → tech badges row (`flex flex-wrap gap-xs`, one `<Badge variant="default">` per `tech` entry) → `mt-auto` footer link (`<a>`, Label role, `text-text hover:text-accent focus-visible:text-accent`, `lucide:github` icon + "View on GitHub", `focus-visible:ring-2 focus-visible:ring-accent/60 focus-visible:outline-none`, matching the exact focus-ring class string already shipped in `Nav.astro`/`Hero.astro`/`Footer.astro`).
- `src/components/Projects.astro` — new component, owns `<section id="projects">` (replaces the empty placeholder currently in `index.astro`):
  - `<section id="projects" class="py-3xl px-lg md:px-xl">` → inner `<div class="max-w-[72rem] mx-auto">` (**arbitrary value, not `max-w-3xl`/etc. — see Spacing Scale gotcha note**) containing:
    1. Section header: eyebrow-free (no Hero-style mono eyebrow here — this is a content section, not a hero), just `<h2>` "Projects" (Display) + subtitle `<p>` (Body, `text-subtext`), `mt-2xl` gap before the grid. **Visual focal point:** the Display-size "Projects" `<h2>` is the primary anchor as the user scrolls into this section; the 6-card grid is the secondary draw (largest area, but no single card competes with the heading for attention); the "More on GitHub" pill row is deliberately the lowest-emphasis element (smaller text, `text-subtext`-weighted, positioned last).
    2. Featured grid: `grid grid-cols-1 md:grid-cols-2 lg:grid-cols-3 gap-lg items-stretch`, rendering the 6 `<ProjectCard />` instances in the exact order from the Project Content table above
    3. `mt-xl` gap, then the "More on GitHub" block: `<h3>` heading (Heading role) + `mt-md` pill row (`flex flex-wrap gap-sm`) of the 6 secondary links
  - No client-side JS required — entirely static markup, same "near-zero JS" discipline as Phase 1/2 (Nav's scroll-listener and Hero's `prefers-reduced-motion`-respecting bounce are the only existing JS/animation on the site; this phase adds neither).
- `src/components/Badge.astro` — **reused unmodified** (existing `default`/`progress` variants cover every badge use in this phase; see Color section for why no new variant was added).
- `src/pages/index.astro` — modified to import `Projects` and replace the existing empty `<section id="projects"></section>` placeholder with `<Projects />`. No changes to `Layout.astro`, `Nav.astro`, `Footer.astro`, or `Hero.astro`.
