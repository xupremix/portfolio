## Spacing Scale

Declared values (must be multiples of 4) — **identical to Phase 1, no new tokens**:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Not used directly in Hero |
| sm | 8px | Gap between eyebrow tag and name |
| md | 16px | Gap between name and tagline |
| lg | 24px | Hero horizontal padding on mobile (`px-lg`, matches Nav) |
| xl | 32px | Gap between tagline and CTA group; hero horizontal padding on tablet+ (`px-xl`, matches Nav) |
| 2xl | 48px | Gap between CTA group and scroll-cue anchor point |
| 3xl | 64px | Nav height (existing, `h-3xl`) — used below to compute hero's available viewport height |

**Hero-specific layout rule [DEFAULT]:**
- Hero section: `min-height: calc(100vh - 64px)` (100vh minus the fixed nav's `3xl`/64px height), so the hero fills the remaining viewport on first load without forcing the user to scroll to see the CTA, on all three required breakpoints (375/768/1440).
- Content is vertically and horizontally centered within that min-height box (flex column, `items-center justify-center`, text-center), matching the "first thing visible on page load" success criterion.
- Content column max-width: `max-w-2xl` (existing Tailwind default scale, not a new custom token) to keep the tagline's line length readable rather than stretching edge-to-edge on 1440px.
- Scroll-cue icon is pinned toward the bottom of the hero box (`absolute bottom-xl` within a `relative` hero container) rather than flowing inline after the CTA group, so it reads as a "there's more below" affordance rather than a fourth stacked content block.

Exceptions: none beyond the layout rule above (no new spacing values introduced).

## Typography

**Identical 4 sizes / 2 weights as Phase 1 — no exceptions, no fluid/clamp sizing added:**

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (Regular, Inter) | 1.5 |
| Label | 14px | 600 (Semibold) | 1.4 |
| Heading | 28px | 600 (Semibold, Inter) | 1.2 |
| Display | 48px | 600 (Semibold, Inter) | 1.1 |

**Hero element-to-role mapping [DEFAULT]:**

| Hero element | Role used | Font family | Notes |
|---|---|---|---|
| Eyebrow / role tag ("ML student, University of Trento") | Label (14px/600/1.4) | JetBrains Mono | Matches Phase 1's own stated intent for this exact use case ("nav 'role' microcopy... e.g. a small tag" — the reserved JetBrains Mono use case). Rendered as a single line; does not wrap. |
| Name ("Filippo Lollato") | Display (48px/600/1.1) | Inter | The hero's largest, dominant element. `<h1>`. **At 375px width may wrap to two lines — this is expected and acceptable; do not add `text-nowrap`, `truncate`, or a fluid font-size exception to force one line.** |
| Tagline (one-line positioning statement) | Heading (28px/600/1.2) | Inter | Rendered as a `<p>` directly under the name. "One-line" describes it as a single sentence, not a no-wrap constraint — it may wrap to 2 lines on 375px without issue. |
| CTA button label | Label (14px/600/1.4) | Inter | Matches Nav's existing Contact CTA button styling exactly (same size/weight/padding pattern: `text-label font-semibold px-md py-xs rounded-md`). |
| Secondary text link label | Label (14px/600/1.4) | Inter | Same size as CTA for visual pairing; distinguished by styling (plain link, not a filled button — see Color section). |

No Body-role text appears in the hero — HERO-01 asks only for name + role/positioning + one-line tagline, so there is no long-form paragraph to justify Body size in this phase.

## Color

**Identical palette as Phase 1 — no new hex values introduced:**

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#1E1E2E` (`--color-base`) | Hero section background (same as page background — hero is not a distinct card/surface, it sits flush with the page) |
| Secondary (30%) | `#181825` (`--color-mantle`) | Not used within the hero itself (hero has no card/panel); remains reserved for Nav/Footer/future section alternation per Phase 1 |
| Accent (10%) | `#CBA6F7` (`--color-accent`) | See reserved-for list below |
| Destructive | `#F38BA8` (`--color-destructive`) | Not applicable — hero has no destructive actions |

Supporting neutrals (unchanged from Phase 1): Primary text `#CDD6F4` (`--color-text`), Muted text `#A6ADC8` (`--color-subtext`), Hairline border `#313244` (`--color-border`).

**Accent reserved for (Phase 2 additions to Phase 1's list — same budget discipline, no blanket accent use):**
- Eyebrow/role tag text color (`text-accent`) — the one deliberate "pop" of color above the fold, consistent with Phase 1's own hint that this exact microcopy pattern is the JetBrains-Mono-plus-accent use case
- Primary CTA button fill (`bg-accent`) — reuses the exact reserved use already declared in Phase 1 ("Primary CTA button fill")
- Secondary text link hover/focus state only (default state uses primary text color `#CDD6F4`) — reuses Phase 1's existing "link hover/focus state" reserved use, not a new grant
- Keyboard focus ring on the CTA button, secondary link, and scroll-cue link — reuses Phase 1's existing "focus ring" reserved use

**Explicitly NOT accent:** the name (`<h1>`) stays in primary text color `#CDD6F4`, not accent — per Phase 1's own rule ("do not use accent for... large surface fills" / more than one element type per view). The name's visual dominance comes from Display-size type weight, not color. The scroll-cue icon is muted (`text-subtext`) at rest, shifting to accent only on hover/focus (reusing the link hover/focus reservation), keeping total accent surface area small and consistent with the 10% budget.

## Component Inventory (Phase 2 scope)

- `src/components/Hero.astro` — new component implementing the layout, typography, color, and copy contract above:
  - `<section id="hero">`, `relative`, `min-height: calc(100vh - 64px)`, flex column centered, `max-w-2xl` content column, `px-lg md:px-xl` horizontal padding (matches Nav's existing padding scale)
  - Eyebrow tag (`<p>`, Label/JetBrains Mono/accent) → `sm` gap → Name (`<h1>`, Display/Inter/text) → `md` gap → Tagline (`<p>`, Heading/Inter/text) → `xl` gap → CTA group (primary button + secondary link, `flex gap-md`, wraps to column on narrow widths if needed) → `2xl` gap-equivalent to an `absolute bottom-xl` scroll-cue link
