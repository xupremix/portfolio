focus-visible:ring-accent/60 focus-visible:outline-none transition-colors">` wrapping `<Icon
name="lucide:chevron-down" width={24} height={24} aria-hidden="true" />`. The icon is decorative

absolutely positioned at `bottom-xl` within the `relative #hero` container (not a flex sibling of the
content wrapper), per UI-SPEC's instruction that it read as a "there's more below" affordance rather
than a fourth stacked content block.

Add a scoped `<style>` block (Astro component styles, same mechanism Nav.astro already uses for

reduce)` rule that sets `animation: none` on `#hero-scroll-cue` — per UI-SPEC's explicit requirement
that any scroll-cue animation must be CSS-only and respect reduced-motion. This is the component's
only styling beyond Tailwind utility classes, matching the project's near-zero-custom-CSS convention.

No client-side `<script>` is needed anywhere in this component — layout, hover, and focus states are
pure CSS/Tailwind, and the bounce is a CSS `@keyframes` animation, not JS-driven.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Hero markup -> browser rendering | Static Astro component renders to static HTML; zero user-controlled input anywhere in the hero |
| CSS-only scroll-cue animation -> user perception | A continuously-running animation can affect users with vestibular/motion sensitivity |
| Hero CTA/scroll-cue hrefs -> navigation | All hrefs are same-page anchor fragments (#projects, #contact) resolving to existing in-page sections |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-------------------|
| T-02-01 | Tampering (accessibility-impacting content behavior) | Hero.astro CSS-only bounce animation | low | mitigate | Animation is gated behind `@media (prefers-reduced-motion: reduce)` to disable/no-op for motion-sensitive users, per UI-SPEC's explicit accessibility requirement; no JS-driven animation, no eval, no dynamic content injection — verified by code review of the scoped `<style>` block |
| T-02-02 | Information Disclosure / Injection | Hero.astro entire component | low | accept | All copy is static, hand-authored, hardcoded strings (name/role/tagline/CTA labels) — no user input, no query-string rendering, no dynamic data interpolation anywhere in the hero; no attack surface for XSS/injection in this phase |
| T-02-03 | Spoofing | Hero CTA/scroll-cue links (#projects, #contact) | low | accept | All hrefs are same-page anchor fragments resolving to existing in-page sections — no external redirect target, no user-controlled URL construction, nothing to spoof |

</threat_model>
